# Duolingo Music 实机练习规程

本目录是一曲一档的实机证据库。处理新的 Duolingo Music 课程、重放已有曲目或补写曲目文档时，执行以下流程。

## 完成标准

- 终极挑战只有在结算页明确显示三颗星时才算完成；进入结算页、播放完毕或获得一颗星都不算完成。
- 保存结算截图，并记录分数、音高、节奏和经验值。证据链接使用仓库相对路径。
- 每首曲子维护一个 Markdown 文件；曲谱事实只放在本目录对应曲目文件，不再重复写入产品文档。

## 新课程的校准顺序

1. 进入钢琴页后先截图，重新测量本课每个可用琴键的中心坐标。每个课程的键盘范围和间距都可能变化，已有 profile 只能作为候选，不能直接假定可用。
2. 从当前谱面识别谱号、拍号、调号、临时升降号、音高、音符时值与休止符。把演奏整理成按时间排序的事件账本；每个音符至少包含 `start_beat`、`pitch`、`duration_beats`。
3. 第一遍同步保存完整的硬件 H.264 画面流和时间戳。第一遍以取得完整谱面、键位和初步时值为目标，不要求零失误；默认不归档连续 PNG。
4. 离线逐帧检查第一遍，冻结完整事件账本，并选取至少两个相隔较远的谱头过线锚点。第二遍使用冻结账本和绝对时钟演奏。
5. 第二遍若仍有偏差，只根据画面流修复对应的相位、BPM 或局部事件。第三遍必须以三颗星结束；三遍仍未完成时，先修正采集、解析或调度流程，再开始新的尝试。

## 双时钟模型

把起奏提示音和连续谱面视为两个阶段：

- **起奏时钟**：第 0 个音只负责触发挑战从提示页进入滚动谱面。它的按下与释放直接锚定设备 ACK，不添加谱面启动补偿。
- **谱面时钟**：第 1 个及后续音符共享稳定的音乐时钟，并统一增加 `score_start_delay_ms`，补偿起奏后 UI 建立滚动所需的时间。

冻结事件的调度公式为：

```text
event 0: deadline = origin_ack + beat × beat_ns - input_advance
event n: deadline = origin_ack + score_start_delay + beat × beat_ns - input_advance
```

后续音符的 DOWN 和 UP 必须使用相同的 `score_start_delay`。这样只平移连续谱面，不改变音符时值。保持乐谱中的整数或半拍位置；UI 启动延迟不得伪装成额外休止符、修改后的拍位或错误 BPM。

## 双锚点拟合

至少使用一个早期锚点和一个中后段锚点。对每个锚点记录谱头中心穿过判定线的时间、对应拍位和实际按键时间。

```text
quarter_ms = (crossing_time_b - crossing_time_a) / (beat_b - beat_a)
bpm = 60000 / quarter_ms
```

先用两个锚点的斜率拟合 BPM，再调整 `score_start_delay_ms`，让早期锚点落到判定线附近。用以下症状选择修复方向：

- 早期正确、后面逐渐变晚：四分音符长度过长，BPM 过低。
- 早期正确、后面逐渐变早：四分音符长度过短，BPM 过高。
- 全程保持近似固定的早或晚：BPM 基本正确，调整启动相位。
- 某个小节突然跳变：检查该处休止符、重复段、漏音、错音或时值，不能用全局 BPM 掩盖事件账本错误。

单个锚点只能识别固定相位，不能可靠区分启动延迟与 BPM 漂移。校准后再用中段和末段锚点验证残差没有随拍数单向增长。

## 演奏与取证

- 使用 `scripts/duolingo-timed-player.py` 的冻结计划模式，让完整事件在一个绝对时钟上运行；按键持续时间来自 `duration_beats`，不能退化为瞬时点击。
- `input_advance_ms` 只补偿设备输入确认延迟；`score_start_delay_ms` 只补偿 UI 从起奏到稳定滚动的相位。两者职责不可互换。
- 演奏中出现提示页重新弹出、灰色音名或“迟了/失误”时，立即停止剩余无效输入，并从录屏定位第一次偏差。
- 每次有效尝试保存冻结计划、播放器参数、设备 ACK 日志、H.264 原流、封装后的 MP4、关键检查帧和最终结算截图。

## 最后有效音符与停止闸门

把计划事件、设备 ACK 和音乐判定分开记录。ACK 只证明输入已送达设备，不能证明音符有效。一次按键只有在后续画面同时出现对应琴键的绿色或黄色命中反馈、谱头经过判定线、连击增加或保持，且没有“要停顿”“太早”“太晚”等错误时，才标记为有效。

第一遍演奏时使用画面流作为曲尾保护：当前音符释放后，如果判定线前方没有可弹音符，并且连续多帧稳定显示休止、谱面尾部或结算过渡，则立即关闭 `playback_gate`。关闭时必须取消未触发的定时器、清空待发送队列并释放仍按住的琴键。采用可取消的短窗口调度，每次只发送下一音或约 200–300ms 的事件；不得把整首曲子的剩余输入一次性排入设备端队列。

离线逐帧复盘时，把每次按键与命中反馈对齐。满足有效条件且位于第一次休止错误或结算过渡之前的最大事件索引，就是 `last_valid_event_index`；同时冻结 `last_valid_pitch`、`last_valid_release_beat` 和 `stop_after_beat`。音名必须结合调号和临时升降号复核，例如画面标记降 B 时写作 `B♭4`，不能记成自然 `B4`。

第二遍及后续演奏只能在以下条件全部成立时发送下一事件：

```text
playback_gate == OPEN
event_index <= last_valid_event_index
current_beat < stop_after_beat
```

最后有效音符按其完整 `duration_beats` 释放；到达 `stop_after_beat` 后进入休止并永久关闭本轮闸门。计划数组中即使仍有事件，也不得继续发送。实时画面若提前检测到稳定曲尾或错误，拥有高于冻结计划的停止优先级。

## 已验证基准：Musette In C Major

第 4 阶段第 14 部分的终极挑战证明了双时钟和双锚点方法：

- 第 0 音为高音 D；第 1 个滚动谱面音为第 8 拍的高音 F。
- 第一锚点：首个 F 的谱头约在 19.150s 过线，旧方案在 19.183s 按下。
- 第二锚点：第 21 拍 F 的谱头约在 27.755s 过线，旧方案在 27.866s 按下并被判“迟了”。
- 两点拟合后采用 90.64 BPM、四分音符 661.9594ms、`score_start_delay_ms=275`、`input_advance_ms=20.5`。
- 79 个计划事件全部获得设备 ACK，但逐帧复核证明 ACK 不等于有效命中：最后有效事件是索引 68、beat 70 的 `B♭4`，在 beat 71 释放；索引 69 的 `C5` 已触发“要停顿”，索引 69–78 共 10 个事件均属曲尾多余输入。
- 最终成绩仍为 1000 分、三颗星、音高 100%、节奏 99%，但结算成绩不能替代曲尾输入审计；冻结计划必须以 `B♭4` 为最后有效音符并在随后休止拍关闭闸门。

验收证据：[三颗星结算页](../../outputs/duolingo-stage4-section14-musette/ultimate/pass-7-two-anchor/final-three-stars.png)、[完整 MP4](../../outputs/duolingo-stage4-section14-musette/ultimate/pass-7-two-anchor/full-stream.mp4)、[设备时序日志](../../outputs/duolingo-stage4-section14-musette/ultimate/pass-7-two-anchor/performance/timing-log.json)。这些数值是该曲目的基准；新课程必须重新测量。

## 曲目文件最低字段

每首曲目文件至少记录：课程位置与挑战类型、标题与版本、谱号、拍号、调号和临时升降号、音域、琴键坐标 profile、逐小节事件、纯音符顺序、所有休止符、时值统计、最终 BPM 与相位参数、完成成绩，以及能够复核结论的相对证据链接。
